## Status Values

- `todo`: Not started.
- `doing`: Currently in progress.
- `blocked`: Started but cannot proceed without a fix or decision.
- `done`: Implemented and verified.
- `deferred`: Intentionally postponed.

## Documentation Timing Rule

- Every implementation task starts by reading `AGENTS.md`, `docs/00-design-doc.md`, `dev_state/PROJECT_ROADMAP.md`, `dev_state/DAILY_LOG.md`, plus task-related docs from the `AGENTS.md` docs map.
- If a task defines or changes API contracts, workflows, guardrails, data-model meaning, RAG behavior, prompts, deployment, observability, or Git workflow, update the related docs before or alongside code.
- If implementation follows already documented behavior, update docs after code only when behavior or contracts changed.
- Project docs are development and maintenance context by default. `docs/prompts/*.md` may become runtime prompts only when code explicitly loads them. Production user QA must not retrieve from project docs unless a future ADR approves it.

## MVP Critical Path

1. FastAPI skeleton.
2. Docker Compose with Postgres, pgvector, and Redis.
3. Database schema and repositories.
4. Notion read-only reader and page indexing.
5. Chunking, embedding, and pgvector upsert.
6. QA over indexed Notion notes with citations.
7. PDF, URL, screenshot, and chat text ingestion.
8. Supplement proposal generation.
9. Accept or reject review flow.
10. Append accepted content to `AI Supplement Zone`.
11. Auto re-index after accepted append.
12. Basic Telegram commands.
13. Evaluation scripts.
14. README demo and mock data.
